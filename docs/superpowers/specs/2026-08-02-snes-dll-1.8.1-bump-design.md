# SNES.dll 1.6.0 → 1.8.1 bump (design)

**Date:** 2026-08-02. **Scope decision:** pure binary bump — Death Pace does
not start consuming the v1.7.0 ROM-identity API (`Smc()` slug, `Rom()`,
`WindowTitle()`). Nothing in the component needs ROM identity today, and the
v1.8.1 release notes warn `SmcChanged()` can fire corrective spurious edges
for up to ~30 s around ROM loads — adopt it only when a feature needs it.

## Why now

- `lib/SNES.dll` is **1.6.0** (`1.6.0+d5777e6`, committed with the
  2026-07-30 scaffold and never updated). snes_offsets has since shipped
  v1.7.0 (ROM identity), v1.8.0 (cooldown rework), and v1.8.1 (sleep
  fusion).
- **Active downgrade hazard:** the live LiveSplit Components folder already
  holds the 1.8.1 `SNES.dll` (deployed 2026-08-02, byte-identical to
  snes_offsets' current Release build). Death Pace's post-build deploy pair
  copies `$(TargetDir)SNES.dll` to Components, so any build of this repo
  silently downgrades the live DLL back to 1.6.0 until `lib/` is bumped.

## The change

Replace `lib/SNES.dll` with
`../snes_offsets/src/SNES/bin/Release/netstandard2.0/SNES.dll`.

**Artifact provenance (verified):** version resource reads
`1.8.1+ef0345e284ef4fc27b36a8a5b05c270d828a2db3` — snes_offsets' main HEAD,
which includes the v1.8.1 release commit — and its MD5
(`c7e92c89ff80fbaa84383d88be136ae7`) matches the copy already running live
in Components. We ship the exact bytes that are already field-tested.

**No code changes.** The consumer contract is unchanged across
1.6.0 → 1.8.1: `Ready()`'s throw contract, `GetOffset()`, `Status()`
snapshot fields, and `Generation` rebind semantics are all stable.
`Snes/StatusDot.cs` already maps the full v1.7/v1.8 state set
(`NoContent`, `Held`, revised colors), and nothing consumes `Smc()`, so the
v1.7.0 slug change is moot.

## Behavioral deltas arriving with the binary (display-level only)

- `NoContent` (orange dot) starts actually occurring — the state is new in
  v1.7.0; the mapping for it was written ahead of the binary.
- The gray cooldown dot becomes rare: since v1.8.0 most discovery declines
  retry hot; cooldowns arm only when re-scanning provably cannot help.
- Binds and fast-reattach get faster (fused verify ~250 ms vs ~866 ms).

None of these touch the calc engine, which is pure and never sees SNES.dll.

## Verification

1. `dotnet build DeathPace.sln -c Release` — clean build; the deploy pair
   re-copies a byte-identical `SNES.dll` to Components, closing the
   downgrade hazard.
2. `dotnet test test/DeathPace.Tests -c Release` — expect 121 green. The
   suite is the regression gate; there is no new code to cover.
3. Live smoke (Andrew, per `docs/TESTING.md` step 1): deathless value
   matches stock Run Prediction digit-for-digit.

## Out of scope

- Consuming `Smc()`/`Rom()`/`WindowTitle()` (future feature, needs its own
  design around the corrective-edge caveat).
- Any status-dot or engine change.
- Un-fusing/rescue behavior details internal to SNES.dll.
